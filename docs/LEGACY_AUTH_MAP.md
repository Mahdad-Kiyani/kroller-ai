## 0. TL;DR / surprising facts (read these first)

1. **The primary working login is passwordless — "SWAT"**, not email+password.
   The client RSA-encrypts a token whose payload `{s: <swirfer-uuid>}` is decrypted
   server-side with the app private key; the member is found by `mem_swirfer` and a
   **PHP server-side `$_SESSION`** is established. `swf_authentication.php:36-126`.
2. **Sessions are PHP `$_SESSION`, not JWT.** There is no JWT anywhere in the legacy
   auth path. The "token" is an RSA-encrypted swirfer UUID (SWAT), single-use per login.
3. **Traditional email+password login is only *partially* implemented.**
   `swf_password_verify()` is called in **exactly one place** — the "don't reuse your old
   password" check inside `handle_forgot_password` (`global_functions.php:729`). There is
   **no** backend action that verifies a password to *log a user in*. The frontend has
   `handlePasswordSubmitTraditional()` (`components_console.js:4469`) but no server
   counterpart was found. **→ Open question Q1.**
4. The subsystem is code-named **"swirfer"** (a.k.a. SWIRF framework, swirflabs). Auth UI
   widgets live in `common/widgets/swirfer.php`; identity column is `mem_swirfer`.
5. Auth logic is **triplicated** across three surfaces (`console/`, `controlpanel/`,
   `www/`) — each has its own `swf_framework/php/swf_authentication.php`. Console is the
   canonical one mapped here. **→ Open question Q2 (confirm they are identical).**

## 2. Data model (legacy tables the auth domain reads/writes)

### `tbl_member` (prefix `mem_`)
Columns referenced by auth: `mem_id`, `mem_name`, `mem_screen_name`, `mem_email`,
`mem_status`, `mem_password_hash`, `mem_swirfer` (UUID v4, **unique**), `mem_role`
(nullable; default applied at login = `"normal_user"`), `mem_locale`,
`timestamp_password_updated`. Profile picture is derived via `get_image('member', id)`.

`mem_status` observed values: `active`, `old_member` (state machine in `check_member`).

### `tbl_valid_link` (prefix `val_`) — the one-time-token / code ledger
Columns: `val_id`, `val_entity`, `val_id_value`, `val_status`, `val_type`, `val_duration`,
`val_timestamp`, `val_member_id`, `val_path`, `val_link`, `val_data` (**jsonb**).

Used for BOTH email-verification codes and password-reset links:

| purpose | val_entity | val_type | val_id_value | statuses |
|---|---|---|---|---|
| signup email code | `email_verification` | `signup` | email | `sent`→`verified`→`success` / `expired` / `fail` |
| password reset link | `member` | `forgot password` | member_id | `sent`→`used` / `superseded` |

`val_data` jsonb shape (union across flows): `{ purpose, code_hash, expires_at, attempts,
member_id, verified_at, expired_at, locked_at, last_attempt_at, account_created_at,
password_reset_at, used_at, superseded_at }`.

### `tbl_swf_application` (prefix `app_`)
`app_public_key`, `app_private_key`, `app_jwk` — RSA keypair used to decrypt the SWAT.
Generated by `generate_ssl_key_pair_application()` (`security_functions.php:257`, RSA-4096, sha512, + JWK export).

### `tbl_template` (prefix `tmp_`)
Email templates fetched by title: `'email verification code'`, `'Reset Password'`.

### 3.1 Password policy (`swf_password_validate_policy`, L334)
Rules (ALL required): length ≥ 8, `[a-z]`, `[A-Z]`, `\d`, symbol from `[@$!%*?&]`, and the
whole string must match `^[A-Za-z\d@$!%*?&]+$` (no other characters allowed).
Return object `{ok:bool, message:string}`, **exact messages**:
- invalid chars → `"Password contains invalid characters."`
- missing a class → `"Password does not meet all requirements."`
- ok → `""`

## 4. Flows

### 4.1 Registration — traditional (email → code → account)
`global_functions.php`

**Step A — `send_email_verification_code($p)` (L149)**
- Normalize `email = trim(strtolower(...))`; require valid email → `"Valid email is required"`.
- If member already exists → `"This email is already associated with an account. Sign in to continue."`
- `duration_seconds` default **1800** (code default; the inline comment "10 minutes" is wrong — it is 30 min).
- `purpose` default `"signup"`.
- code = `random_int(100000, 999999)` (6 digits).
- `code_hash = hash_hmac('sha256', code.'|'.email, app_secret)` where
  `app_secret = $_SESSION['app_secret'] ?: ($_SESSION['project_name'] ?: 'swf').'_secret'`.
- Insert `valid_link` (`email_verification`/`signup`/`sent`, data `{purpose,code_hash,expires_at,attempts:0}`).
- Send email via `EmailService` DB template `'email verification code'`, merge `{VERIFICATION_CODE}`.
- On send failure → mark `fail`, return `"Failed to send verification code"`.
- Success returns `{success:true, code}` (⚠️ code returned in payload — "for testing"; **strip in prod**).

**Step B — `verify_signup_code($p)` (L294)**
- Require valid email + `^\d{6}$` code (`"Verification code is required"`).
- Recompute `code_hash`; fetch latest `valid_link` (`email_verification`/`signup`, id_value=email, `ORDER BY val_timestamp DESC LIMIT 1`).
- Status branches: not found → `"Code not found. Please request a new code."`; `verified` → success (returns existing `codex_creationis`); `expired`/`fail` → `"Code is no longer valid…"`.
- Expiry (`now > expires_at`) → mark `expired`, `"Code expired. Please request a new code."`
- Brute-force: `attempts >= 5` → mark `fail`, `"Too many attempts. Please request a new code."`
- Mismatch (`!hash_equals`) → `attempts++`, `"Incorrect code"`.
- Success → status `verified`, return `{success:true, message:"Verified", codex_creationis: val_id}`.

**Step C — `create_account_traditional($p)` (L473)**
- Inputs: `email`, `name` (**≥4 chars**, else `"Name is required"`), `password`, `codex_creationis`, `purpose`. (`gender`/`birthdate` present but commented out.)
- Validate token: `val_id=codex_creationis`, entity `email_verification`, type `signup`, status `verified`; `id_value` must equal email (`"Verification token mismatch"`); not expired (`"Verification expired"`).
- Re-check member not exists (`"Member already exists"`).
- Policy check → bcrypt hash → `insert_member_with_unique_swirfer({email,name,screen_name:name,status:'active',password_hash})`.
- Call `additional_create_account($member_id)` if defined (extension hook).
- Mark `valid_link` `success`. Return `"Account created successfully."`

### 4.2 Login
1. **`check_member($p)` (L785)** — email lookup, returns a **state** to drive the UI:
   `{member_exists, message, member_id, member_name}` where `message` ∈
   `password` (active + has hash) / `welcoming_old_member` (active w/o hash, or status `old_member`) /
   `sign_up` (no such member) / `""` (other status).
2. **Password submit** — frontend `handlePasswordSubmitTraditional()` exists; **no backend verifier found (Q1).**
3. **`VALIDATE_SWAT` (`swf_authentication.php:36`)** — RSA-decrypt SWAT (`OPENSSL_PKCS1_PADDING`) → `{s:swirfer}`;
   `SELECT * FROM tbl_member WHERE mem_swirfer=? AND mem_status='active'`; on hit set session:
   `swirfer, member_id, member_name, member_screen_name, member_email, member_profile_picture,
   member_role (default "normal_user"), member_locale, signin_attempt_counter=0`; echo `"signed_in"`.
   On miss → `throw_error('auth_no_such_member', severity 5)`.
4. **`update_old_member($p)` (L827)** — migrates an `old_member` (email+name+swirfer) to `active`.

### 4.3 Logout
`SIGN_OUT` action (`swf_authentication.php:157`) unsets all `member_*`/`swirfer` session keys, echoes `"signed_out :"`. Also `console/logout.php`.

### 4.4 Forgot password
**Send — `send_forgot_password($p)` (L857)**: inputs `member_id`, `domain_name`. Builds reset token via
`handle_envelope(json{expired, member_id})`, `confirm_url = {domain}/path/{token}`. Inserts `valid_link`
(`member`/`forgot password`/id_value=member_id, `timestamp_expired = +1 day`, `data{member_id}`). Emails
template `'Reset Password'` merging `{{LINK}}`,`{{NAME}}`,`{{EXPIRED}}` (from/reply `no-reply@krollerma.io`, "Kröller M&A").

**Complete — `handle_forgot_password($p)` (L634)**: inputs `valid_link_id`, `password`. Policy check; load
`valid_link` (`member`/`forgot password`/`sent`); reject if `used`/`success` (`"Reset token already used"`);
member from `val_data.member_id`; block reusing current password (`swf_password_verify` →
`"New password must be different from the current password"`); bcrypt hash → update member
(`status:'active', password_hash, timestamp_password_updated`); mark token `used`; supersede sibling tokens.
Return `"Password updated successfully."`

> ⚠️ Legacy inconsistency to preserve/decide: `send_forgot_password` writes `val_type='forgot password'`
> (space) and `handle_forgot_password` reads `'forgot password'`, but the sibling-invalidation SQL filters
> `val_type='forgot_password'` (underscore) — so **the supersede step currently no-ops**. **→ Q3.**

## 7. Parity Ledger (constants that MUST be reproduced exactly)
- bcrypt **cost 12**; `password_needs_rehash` on same params.
- Password policy regex set + the two exact error strings (§3.1).
- Verification code: `random_int(100000,999999)`; `code_hash = HMAC-SHA256(code|email, app_secret)`; TTL **1800s**.
- Reset link TTL **1 day**; url-safe-base64 AES-128-CBC envelope.
- Brute-force max **5** attempts (verify code) and unique-swirfer retry max **5**.
- `valid_link` status state machine + `val_data` json keys (§2).
- Swirfer identity = **UUID v4**, unique per member.
- Session/identity payload fields (§4.2 step 3) — whatever token we issue must carry the same identity set.
- Every user-facing message string quoted above (regression-test each verbatim).
